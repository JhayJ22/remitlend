# Security Scanning

RemitLend runs several automated security scans as part of the CI/CD pipeline.

## Container vulnerability scanning

Trivy scans are run against every staged image on every push to `main`:
- **HIGH** severity findings: logged as warnings (non-blocking)
- **CRITICAL** severity findings: block the deploy

Results appear in the repository's **Security → Code scanning** tab via SARIF
upload.

Known-safe CVEs that have been assessed and accepted are tracked in
[`.trivyignore`](../../.trivyignore) with a justification comment and a
`Review-by` date.

## Static analysis (CodeQL)

GitHub CodeQL runs on every PR and push to `main`, covering JavaScript/TypeScript
source for injection flaws, prototype pollution, and similar SAST findings.
See [`.github/workflows/codeql.yml`](../../.github/workflows/codeql.yml).

## Supply-chain provenance (#361)

Release images are:
- **Signed** with [Sigstore/cosign](https://docs.sigstore.dev/) keyless signing
- **SLSA Level 3** provenance generated by the
  [slsa-github-generator](https://github.com/slsa-framework/slsa-github-generator)
- **SBOM** attached as cosign attestations (SPDX JSON)

Staging builds on every merge to `main` are also signed with cosign.

See [`.github/workflows/release-provenance.yml`](../../.github/workflows/release-provenance.yml)
for the full workflow.

## Dependency risk triage (#362)

Dependabot monitors all dependency ecosystems (npm backend, npm frontend, npm
scripts, Cargo, GitHub Actions) on a weekly schedule. Security advisories get
their own dedicated PR group (`*-security`) so they are not blocked behind a
larger routine-update batch.

Minor and patch updates are auto-merged once CI passes via the
[dependabot-automerge workflow](../../.github/workflows/dependabot-automerge.yml).
Major bumps are always opened as individual PRs requiring explicit review.

## Outbound egress policy (#363)

Permitted outbound network destinations for every RemitLend service are
documented in [`docs/EGRESS-POLICY.md`](../EGRESS-POLICY.md).

Enforcement mechanisms include:
- Docker `internal: true` network for database and cache tiers
- `cap_drop: [ALL]` removing `CAP_NET_ADMIN` and `CAP_NET_RAW`
- Application-layer SSRF guards on webhook delivery and HTTP client
